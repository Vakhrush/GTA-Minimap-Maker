# Как работает аддон

Аддон использует portrace.exe для векторизации предварительно настроенных снимков viewport, и JPEXS для редактирования и создания .gfx.

На основе многоэтажного интерьера мной создан шаблон .gfx. В шаблоне значения, необходимые к изменению, и bounds спрайтов - поправлены для максимальной универсальности.

В данном аддоне используется метод наложения масштаба и расположения спрайта поверх шаблонных bounds. Во всех новосозданных интерьерах, протестированных мной, всё работает корректно. Сбой масштаба или положения миникарты могут быть скорее исключением с определенными интерьерами.

При первом запуске укажите в настройках путь к JPEXS и путь для сохранения .gfx. При пустой строке .gfx сохранится в папку с проектом.

В панели аддона нажмите Refresh minimap. Аддон автоматически выполнит следующее:

- Вид переключится на shade, все entity перекрасятся в цвет пропов как на миникартах ванильной ГТА, фон viewport сменится на цвет стен или фона как на миникартах ГТА, аддон постарается найти при помощи Sollumz shell и покрасит его тоже. Отключится cavity, отображение теней, вид отображения переключится на flat - чтобы всё максимально соответствовало миникартам ГТА.

- аддон отключит коллизии при помощи Sollumz, скроет двери (все пропы привязанные к порталам) - по желанию это можно отключить в настройках аддона.

- найдет MLO и заполнит автоматически MLO name. Если этого не произошло, внесите его вручную и снова нажмите Refresh minimap.

- проанализирует Rooms в ytyp в Sollumz, посчитает количество этажей.

- создаст камеры в соответствии с количеством этажей, расположит камеры по высоте этажа. Рассчет высоты выполняется по найденному MLO: при помощи материалов коллизий, привязанных к Room (а Room естественно связаны с этажами), выделит плоскости и посчитает расстояние между ними. Используется усредненный показатель, если интерьер с перепадами. Если не выйдет посчитать высоту одного из этажей, в крайнем случае используется высота уже известных этажей.

- Зная высоту этажей, настроит у камер clip start / clip end с небольшим запасом, который можно настроить по необходимости в параметрах аддона. Использовать clip start / end необходимо для предотвращения захвата камерами нижних этажей, в процессе сохранения .gfx.

- Далее автоматически настраивается позиционирование камеры в центре видимой геометрии MLO и также настраивается orhographic scale до границ MLO с небольшим запасом, который тоже можно настроить в параметрах аддона.

Далее при нажатии "Create .GFX" аддон делает следующее:

- Создает снимки по отдельности shell, entities, пропов с custom_color и каждого этажа по очереди.

- Полученные снимки обрабатывает portrace.exe с заданными мной параметрами (которые можешь изменить в operator.py , см. def run_potrace(pbm_path, svg_path)). Portrace.exe на выходе создаёт черно-белые контуры в .svg.

- Полученные .svg аддон собирает в единый .svg с покраской внутренних слоёв в заданные цвета

Слои в самом .svg располагаются в заданном порядке с некоторыми условиями, но в общем принцип такой: сначала фон, далее shell, entity, walls (опционально), custom color. В слое walls находятся все объекты, покрашенные в цвет walls, а также контур shell переведенный в обычный вектор, если выбран в параметрах такой способ построения фона.

- К каждому .svg присваивается соответствующее имя: 1, 3, 5, 7, 9.

- Далее при помощи JPEXS подготовленный шаблон аддона intEXAMPLE.gfx выгружается в .xml.

- MLO name хешируется аддоном и вносится в соответствующие поля .xml. В графическом интерфейсе JPEXS это frame 2 - FrameLabel (name: "INT*"), где вместо звёздочек хешированное имя, также вносится в поле ExporterInfo (int*). В ExportAssets строка с MLO name вносится без хеширования. В Metadata вносится текущая дата модифицирования и добавляется строка с автором/публишером (эту строку можно изменить в параметрах аддона).

- В соответствии с формулой в .xml вносятся корректировки дочернего масштаба и трансформации спрайтов, в зависимости от количества этажей (формулу см. в operator.py, строка 176 или поиск по фразе "TranslateX&TranslateY"). 1 спрайт это подвальный этаж (floorId -1), 3 спрайт это нулевой этаж (floorId 0), и так далее до 9 спрайта, который является третьим этажом (floorId 3). В шаблоне родительский BOUNDS SCALE равен 20480. Из каждой камеры берется значение ортографического масштаба и переводится в внутреннюю единицу измерения, также и с данными расположения камер по осям X и Y. Таким образом спрайт смещается относительно pivot в своих единицах измерения, также как и ваш интерьер MLO смещен в Blender относительно world origin.

- Готовый intEXAMPLE.xml при помощи JPEXS собирается в .swf, а .swf переименовывается в .gfx.

- В intEXAMPLE.gfx импортируются созданные .svg без UPDATE BOUNDS.

- intEXAMPLE.gfx переименовывается в int***.gfx, где звездочки это хешированное MLO name.

- удаляются временные файлы из этой же папки.

Если необходимо, вы можете отредактировать исходные .svg при помощи любого векторного редактора, например при помощи Inkscape. Отредактированные inkscape легко импортируются вручную через JPEXS - import shapes - указывается папка с .svg.

**Важно:** при импорте не используйте import shapes - update bounds.

## Процес подготовки миникарты в Blender

В Blender в панели аддона можно настроить Minimap Colors.

В самом Blender можно при помощи примитивов и обычного скрытия лишних пропов добиться миникарты требуемого качества.

Рекомендую сохранить проект перед внесением изменений в сцену.

В настройках камеры отрегулируйте clip start /end, если остаются какие-то контуры пропов с нижележащих этажей.

Если у вас MLO интерьер очень габаритный и пропы отображаются как-то размыто (как кляксы), попробуйте выставить в параметрах аддона ультра качество, или вручную значения выше. Имейте ввиду, что чем выше значение, тем дольше Blender будет рендерить и векторизировать слои.
